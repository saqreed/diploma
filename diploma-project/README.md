# Настраиваемые правила антифрода

FastAPI + React/TypeScript/Vite + PostgreSQL. Существующий каркас сохранён; прежняя тема трёхфакторной аутентификации историческая. ML, TOTP и поведенческих профилей в актуальной версии нет. Внутренние материалы диплома находятся вне приложения и не публикуются.

## Локальный запуск (PowerShell 7, Docker Desktop, Node >=22.22)

Из этой папки:

```powershell
./scripts/prepare-local.ps1
docker compose config --quiet
docker compose up -d --wait postgres
docker compose build backend
docker compose --profile tools run --rm bootstrap
docker compose up -d --wait backend
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. API http://127.0.0.1:8000, документация API /docs, проверка доступности /health. Bootstrap выполняется явно: применяет миграции 1–6, создаёт отдельные роли PostgreSQL и отсутствующие учебные записи. Повтор сохраняет существующие записи. Данные остаются в postgres_data; для обычного перезапуска используйте `docker compose restart`. Удалять том не требуется. Для проверки production-интерфейса вместо dev используйте `npm run build`, затем `npm run preview` (тот же порт, сначала остановите dev).

Подготовленные аккаунты: admin, specialist, employee, employee2, manager, accountant. Учебный пароль создаётся случайно в локальном `.env` (DIPLOMA_SEED_PASSWORD). Откройте файл локально; не включайте его содержимое в отчёты. Скрипт заполняет только отсутствующие значения. Общий пароль аккаунтов допустим только в этом локальном учебном стенде. Runtime backend не получает пароль владельца PostgreSQL.

Источник БД по умолчанию ограничен сервером postgres и таблицей demo.requests. URL вводится администратором с отдельной ролью diploma_reader и локальным DIPLOMA_READER_PASSWORD. Расширение серверного allowlist требует явной настройки подключения; произвольный SQL не поддерживается. Ключ шифрования источников нельзя терять или менять при сохранении существующих настроек.

## Проверки

```powershell
# В собственной среде Python 3.12 backend:
python -m pip install -e ".[test]"
python -m pip check
python -m pytest
python tests/http_scenario.py --env-file ../.env
python tests/http_states.py
python tests/http_mechanisms.py
python tests/http_settings.py
python tests/http_source.py
python tests/http_demo_source.py
# Проверяет обычный перезапуск PostgreSQL и backend:
python tests/http_restart.py
# frontend:
npm run check
```

Контейнер использует точные версии из backend/constraints-linux.txt. Локальная Windows-среда имеет отдельный набор платформенных зависимостей. Скопированная старая .venv содержит путь прежней машины и не пригодна для запуска: создайте новую, сохранив старую до отдельного решения. Строгий режим предупреждений тестов сохранён; совместимая связка FastAPI/Starlette/AnyIO закреплена и проверена в чистом Linux-контейнере.

Проверки HTTP запускаются из backend и создают записи с префиксом QA. Секреты читаются локально, не печатаются. http_registry_reset.py явно возвращает демо в исходное состояние, предварительно архивируя заявки; он сохраняет журнал и исполненные операции. http_outbox.py требует временную реплику backend на localhost:8101 с недоступным DIPLOMA_ANTIFRAUD_URL; её запуск и очистка описаны в локальном отчёте проверок. Не используйте эти сценарии с реальными данными.

В интерфейсе: администратор настраивает приложение/поля, правила, шаблоны, списки и источник; специалист работает с журналом; остальные роли работают с демо. Сумма выше 10 000 ₽ по начальному правилу требует специалиста. APPROVED антифрода — разрешение действия, «Согласовано руководителем» — отдельный статус заявки. Оба обязательных этапа сохраняются. В настройках есть явный возврат демо с контрольной фразой; старые данные сохраняются в demo.reset_archives, история расчётов начинается с нового history_from.

## Границы гарантии демо

Запрос проверки и фактическое событие сохраняются отдельно. Окончательная транзакция демо блокирует решение и заявку, сравнивает все проверенные значения, срок и полномочия, записывает условное действие, однократное использование решения и outbox. Отмена использует ту же блокировку решения. Успешная отмена исключает выполнение; после выполненного действия отмена отклоняется. Deadline проверяется непосредственно перед записью результата; завершение уже допущенной транзакции может произойти позже. Это гарантия локального условного действия в общей PostgreSQL, не распределённого платежа. Настоящих платежей нет.

Состояние полного объёма и доказательства проверок — в локальной документации, CURRENT_STATUS.md и таблице соответствия требований. Нагрузочные цели и совместимость браузеров не считаются достигнутыми по сборке или наличию страницы.

Время срока берётся из PostgreSQL. Перед демонстрацией проверьте синхронизацию часов хоста и Docker Desktop: при смещении часов VM назад срок по внешним часам не гарантируется. Стенд слушает только 127.0.0.1. Chrome/Firefox в Windows не запустились (`spawn UNKNOWN`); точная причина не установлена. Нельзя заменять их проверку результатом Edge.

## Локальный HTTPS

После production build можно включить отдельный вход Caddy, не останавливая dev/preview:

```powershell
docker compose -f docker-compose.yml -f docker-compose.https.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --wait web
./scripts/export-local-ca.ps1
# Из backend, с установленными test-зависимостями:
python tests/http_tls.py --ca "$env:LOCALAPPDATA/DiplomaValidation/tls/root.crt"
```

Адрес https://localhost:8443 (также поддерживается https://127.0.0.1:8443). Caddy создаёт локальный центр сертификации; закрытые ключи остаются в Docker-томе `local_tls_data`. Скрипт экспортирует только публичный `root.crt`. ОС и браузеры автоматически ему не доверяют: импорт доверия к этому локальному CA в выбранный браузер/профиль — отдельное действие пользователя. Не отключайте проверку сертификата и не используйте обход предупреждения как доказательство защиты. HTTP-тест явно доверяет этому файлу и проверяет имя сервера; дополнительно доказывает отказ неизвестному CA и неверному имени. TLS 1.3, реальный вход/выход и Secure/HttpOnly/SameSite cookie проверены, системное хранилище доверия не менялось.

HTTPS-вход отдаёт production-сборку и настоящий API. HTTP 5173/8000 остаётся отдельным локальным режимом разработки; его нельзя публиковать в сеть. Внутренние соединения компонентов относятся к доверенной границе одного Docker-хоста. Сетевой стенд для других машин требует согласованного имени, доверенного им сертификата и отдельной настройки портов. Ни Caddy, ни PostgreSQL сейчас не открыты в локальную сеть. Не удаляйте TLS-том при сохранении настроенного доверия.

## Браузерные проверки в отдельном локальном контейнере

Если браузер не запускается в Windows, подготовлен отдельный QA-образ с Chrome for Testing 154.0.8037.92 и Firefox 157.0, без изменения контейнеров приложения. Контекст сборки — только `frontend/tests`; внутренние документы и `.env` в образ не копируются. Для запуска нужны работающий backend, `frontend/dist` после production build и приватный fixture из нагрузочного сценария (см. локальный отчёт проверок).

```powershell
# Из diploma-project, по одному сценарию за раз:
./scripts/test-browser-container.ps1 -Browser chromium -Build
./scripts/test-browser-container.ps1 -Browser chromium -Scenario editor
./scripts/test-browser-container.ps1 -Browser firefox
./scripts/test-browser-container.ps1 -Browser firefox -Scenario editor
```

Сценарий `editor` явно возвращает учебные заявки в исходное состояние и сохраняет прежние записи в архиве. Запуск использует настоящий backend и сохранённые данные, не моки. Контейнер не публикует порты на хост; после проверки удаляется. Только два учебных секрета и имя БД передаются через временный файл с чтением; файл удаляется после запуска. Отчёты записываются только в локальную `diploma-docs/07_reports`, снимки — в её приватную `.browser-qa/screenshots/<browser>/<scenario>`. Сборка самого QA-образа не подтверждает успешность браузерных сценариев: результат должен быть сохранён отдельным отчётом.

05.10.2026 Chrome и Firefox в Linux прошли оба сценария, включая все восемь редакторов, ошибки без потери ввода, переименование/защиту соседних полей и русский текст, сохранённый сервером. Ошибок JavaScript нет; основные экраны на истории 10k/20 правил ≤2 с. Это отдельное доказательство от Edge Windows. Для stock Firefox BiDi тест использует клавиатуру: его автоматические fill/Unicode insertText могут обойти обработчик React; завершающее обычное редактирование сохраняет полный введённый текст. Тест не устанавливает состояние React и не подменяет API. Функциональные browser-прогоны используют HTTP только внутри локального QA; проверка HTTPS описана выше.
