# Подключения и учебные источники

Расширение от 12.11.2026. PostgreSQL остаётся внутренним хранилищем. PostgreSQL, MySQL и MongoDB используются только для полей текущей операции. История поступает отдельно через API. Один профиль подключения на приложение; у каждого поля ровно один источник: API или БД.

## Запуск без сброса основного стенда

Из корня репозитория в PowerShell 7:

```powershell
./scripts/prepare-source-lab.ps1
docker compose build backend
docker compose --profile tools run --rm bootstrap
docker compose --env-file .env --env-file .env.sources -f docker-compose.yml -f docker-compose.sources.yml --profile sources up -d --wait --wait-timeout 180 source-pg source-mysql source-mongo backend
./scripts/update-source-inventory.ps1 -Watch
```

Последняя команда работает в отдельном терминале и обновляет инвентарь каждые 10 секунд. Для разового обновления уберите `-Watch`. Фронтенд запускается обычной командой `npm --prefix frontend run dev`. Адрес: http://127.0.0.1:5173/settings → «Подключения».

Основной том `postgres_data` сохраняется. Учебный профиль использует три отдельных тома `source_pg_data`, `source_mysql_data`, `source_mongo_data`. Порты источников на хост не публикуются. Не применяйте `down -v`. Секреты генерируются в игнорируемом `.env.sources` и не заменяют основной `.env`. Начальные записи и пользователи создаются при первом запуске новых томов; последующий запуск их не перезаписывает.

| Источник | Проверенный образ | Ресурс | Ключ |
|---|---|---|---|
| PostgreSQL | `postgres:17.11-bookworm` | База `lab`, `public.operations` | `id`, целое число |
| MySQL | `mysql:8.4.8` | База `lab`, `lab.operations` | `id`, целое число |
| MongoDB | `mongo:8.0.17` | База `lab`, коллекция `operations` | `id` (число) либо `_id` (ObjectId) |

Пользователь чтения — `lab_reader`, пароль — `SOURCE_LAB_READER_PASSWORD` в `.env.sources`. `lab_denied` и `lab_writer` нужны только отрицательным тестам: у первого нет доступа, у второго есть права записи. Для обычной настройки они не подходят. Синтетическая запись `id=1`: сумма `11500.1250`, строка «Учебный получатель», логическое `active=true`. Для MongoDB `_id=000000000000000000000001`. Не используйте эти учётные записи вне учебной среды.

## Путь в интерфейсе

1. В каталоге создайте отдельное приложение с действием и типизированными полями. При необходимости задайте статусы событий и варианты значений полей. Статусы другого приложения не подставляются.
2. Откройте «Подключения», выберите приложение и обнаруженный сервис либо «Добавить вручную». Разрешённые базы и адреса предлагаются из серверной политики.
3. Введите пользователя и пароль. «Проверить доступ и получить поля» проверяет реальную аутентификацию и права чтения. Успешный TCP-пробник этого не заменяет.
4. Выберите таблицу/коллекцию, ключ и источник каждого поля. Несовместимые типы помечены в списке. Сопоставление записывается вместе с выбором API/БД только при сохранении.
5. Проверьте чтение по ключу `1`. Форма разрешит сохранение только после успешного теста текущих настроек. Ошибка пробы ничего не сохраняет. Значения записи не возвращаются из административного теста; выводятся имена прочитанных полей.
6. Явно сохраните источник. Создайте правило на поле суммы, например `amount ≥ 10000.12 → рассмотрение`. Приложение передаёт `/api/checks` с `record_key="1"`. Решение содержит точную нормализованную сумму `11500.125`, а журнал объясняет срабатывание. Никакого выполнения операции этот запрос не производит.

Смена адреса, порта, типа, базы или пользователя требует нового пароля. Пустое поле использует сохранённый секрет только при полном совпадении подключения. URL не возвращается в API; секрет шифруется прежним ключом Fernet. Параметры драйвера в URL запрещены. Черновики живут в памяти вкладки и переживают переходы между разделами, но не перезагрузку страницы; при выходе из аккаунта очищаются. Пароли не записываются в localStorage/sessionStorage.

## Граница обнаружения

`config/source-policy.json` — доверенная конфигурация оператора: точные тип, хост, порт, базы, ресурсы и разрешённые поля. Она читается при обращении, а не зашита во frontend. Для прежнего запуска без дополнительного Compose-файла сохранён PostgreSQL-список `DIPLOMA_SOURCE_HOSTS`/`DIPLOMA_SOURCE_TABLES`, порт 5432.

Помощник `scripts/update-source-inventory.ps1` выполняет только чтение списка запущенных контейнеров выбранного Compose-проекта и их **меток**. Он не читает окружение контейнеров и не передаёт backend Docker socket. Добавленный учебный сервис с метками `diploma.source.kind`, `diploma.source.host`, `diploma.source.port` появляется после обновления без правки frontend. Для подключения к нему оператор отдельно разрешает endpoint и ресурсы в политике. Неизвестный тип остаётся неизвестным; тип не угадывается по порту.

Файл `config/local-inventory/inventory.json` обновляется атомарно и монтируется только для чтения. Секция автоматически проверяется при открытии и кнопкой «Обновить». Пробы выполняются лишь для пересечения инвентаря с политикой: максимум 64 записи, четыре одновременных соединения, 1,5 секунды на соединение. Подключение к порту не отправляет учётные данные. Остановленный сервис исчезает после очередного обновления инвентаря, но его сохранённые профили остаются. Если помощник остановлен, показывается время и предупреждение об устаревшем инвентаре. Ручной путь остаётся доступен.

## Адаптеры и ограничения

- Общий контракт: проверенные метаданные и чтение одной записи. При чтении повторно проверяются политика, права и типы. Запрашивается не более двух совпадений: ноль или два дают ошибку. Произвольных SQL/NoSQL-запросов нет.
- PostgreSQL: прежний SQLAlchemy/asyncpg, транзакция READ ONLY и серверный тайм-аут. Сохранены проверки прав записи на таблицу и столбцы; административные роли отклоняются.
- MySQL: SQLAlchemy + `asyncmy 0.2.11`, READ ONLY, ограничение времени SELECT. Допускается пользователь с прямыми SELECT/USAGE/SHOW VIEW. Делегированные роли, неизвестные разрешения и GRANT OPTION отклоняются: первая версия не пытается доказать безопасность произвольной иерархии ролей. BOOL распознаётся только для разрешённого в политике TINYINT(1); значения кроме 0/1 отклоняются.
- MongoDB: `PyMongo 4.18.0`, `AsyncMongoClient`, проверка эффективных привилегий через `connectionStatus`. Разрешены известные права чтения. Поля и их типы задаёт оператор; коллекция для построения формы не сканируется. Ограниченная проекция и `limit(2)`. Отсутствующие обязательные поля, массивы/объекты и несовпадающие типы запрещают действие. ObjectId отличается от строкового ключа, Decimal128 преобразуется без округления.
- Суммы нормализуются через Decimal и передаются строками. Ошибка чтения даёт запрещающий результат. Проверенные снимки, сроки решений, доставка событий и протокол исполнения не расширялись.
- В учебной закрытой сети TLS выключен явной серверной политикой. Для внешнего сервера задайте `tls: true`: проверка системного CA и имени включена. В UI нет обхода проверки сертификата. Удалённые TLS-серверы в этой работе не проверялись. Поддерживается один MongoDB endpoint, без SRV/replica-set URI и произвольных параметров URL.
- Таблица `antifraud.sources` не меняет схему: тип определяется по зашифрованному URL. Поэтому прежние PostgreSQL-профили и шифротекст не требуют конвертации. Совместимая миграция 8 лишь добавляет варианты статусов `SUCCESS` в каталог демо, сохраняя уже заданные значения. Старый формат API с `url` поддержан; небезопасный профиль теперь отвергается уже при сохранении.

## Проверка

```powershell
node scripts/test-source-integrations.mjs
npm --prefix frontend run check
# В подготовленной Python-среде:
cd backend
python -m pytest
```

Интеграционный сценарий создаёт отдельные приложения `qa-connectors-*`, не меняет привязку рабочего демо и не удаляет данные. Проверяет три живые БД, политику, типы, деньги, логические значения, REVIEW, повтор запроса, отсутствие записи/поля, неоднозначный ключ, неверные пароли, роли без прав и с записью, несовместимые ресурсы/поля и неизменность сохранённого профиля после ошибки. Для исторического PostgreSQL-контракта: `backend/tests/http_source.py`.

Официальные основания: [SQLAlchemy asyncmy](https://docs.sqlalchemy.org/en/20/dialects/mysql.html#module-sqlalchemy.dialects.mysql.asyncmy), [MySQL SHOW GRANTS](https://dev.mysql.com/doc/refman/8.4/en/show-grants.html), [MongoDB connectionStatus](https://www.mongodb.com/docs/manual/reference/command/connectionstatus/), [PyMongo AsyncMongoClient](https://pymongo.readthedocs.io/en/4.18.0/api/pymongo/asynchronous/mongo_client.html), [PostgreSQL проверки прав](https://www.postgresql.org/docs/17/functions-info.html).
