# Настраиваемые правила антифрода

[![CI](https://github.com/saqreed/diploma/actions/workflows/ci.yml/badge.svg)](https://github.com/saqreed/diploma/actions/workflows/ci.yml)

Учебная веб-система для проверки действий приложения по правилам администратора. Приложение задаёт типы событий и поля; движок работает с этим каталогом. Сервис возмещения расходов демонстрирует подключение: сотрудник создаёт заявку, руководитель согласует её, бухгалтер выполняет условную выплату. Настоящих платежей нет.

Backend — FastAPI, SQLAlchemy и PostgreSQL; интерфейс — React, TypeScript и Vite. Компоненты и данные запускаются локально через Docker Compose. Интерфейс на русском языке.

## Возможности

- Приложения, типы событий и типизированные поля; визуальная настройка правил, шаблонов, списков наблюдения и исключений.
- Восемь механизмов: условия И/ИЛИ/НЕ, повторы, количество событий, суммы и уникальные значения, последовательности, обязательное предыдущее событие, сравнение связанных данных и новизна значения. Для истории задаются период, группировка и статусы.
- Реакции с фиксированным приоритетом: запрет → ручное рассмотрение → подтверждение инициатором → разрешение. Если нужны оба обязательных этапа, одобрение специалистом сохраняет требование подтверждения.
- Журнал с фильтрами, причинами решения, проверенными значениями и историей переходов. Запрос проверки и сообщение о фактическом событии сохраняются отдельно; повторная доставка не создаёт дубликаты.
- Подключение к PostgreSQL только для чтения: таблица, ключ поиска, разрешённые поля и сопоставление. У поля один источник; ошибки источника или обязательного поля не дают разрешения. Произвольный SQL не поддерживается.
- Демо: заявки, редактирование, согласование, условная выплата, история, выгрузка реестра и возврат учебных заявок в исходное состояние с архивом.

## Структура репозитория

Приложение находится прямо в корне, без вложенной папки `diploma-project`.

```text
backend/                  API, движок правил, миграции и тесты
frontend/                 интерфейс и браузерные сценарии
scripts/                  подготовка окружения и локальные проверки
infra/                    настройка HTTPS
.github/workflows/ci.yml   проверки GitHub Actions
docker-compose.yml        PostgreSQL, backend и служебный bootstrap
docker-compose.https.yml  дополнительный HTTPS-вход
.env.example              пример конфигурации без секретов
```

Внутренние материалы диплома, локальный `.env`, отчёты, сертификаты и данные не входят в Git. Имя Compose-проекта `diploma-project` сохранено для совместимости существующих сетей и томов; это идентификатор стенда.

## Быстрый запуск

Требуются работающий Docker Desktop с Compose, PowerShell 7 и Node.js ≥22.22. В CI используется Node.js 24.19.0. Python на хосте нужен только для локальных backend-тестов; контейнер использует Python 3.12.14.

Все команды ниже выполняются из корня репозитория, если явно не указан переход в `backend`.

```powershell
git clone https://github.com/saqreed/diploma.git
cd diploma

docker version
docker compose version
if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
./scripts/prepare-local.ps1
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90 postgres
docker compose build backend
docker compose --profile tools run --rm bootstrap
docker compose up -d --wait --wait-timeout 90 backend

npm --prefix frontend ci
npm --prefix frontend run dev
```

Для уже существующей рабочей папки начинайте с проверки Docker, пропустив `git clone` и `cd diploma`. Скрипт создаёт только отсутствующие секреты и сохраняет существующие значения. Bootstrap применяет миграции, настраивает роли БД и создаёт отсутствующие учебные записи; повторный запуск сохраняет данные. Runtime backend не получает пароль владельца PostgreSQL.

| Адрес | Назначение |
| --- | --- |
| http://127.0.0.1:5173 | Интерфейс |
| http://127.0.0.1:8000/health | Доступность API |
| http://127.0.0.1:8000/docs | OpenAPI |

Для проверки production-интерфейса остановите dev-сервер и выполните из корня:

```powershell
npm --prefix frontend run build
npm --prefix frontend run preview
```

### Учебные аккаунты

| Логин | Роль |
| --- | --- |
| `admin` | Настройка антифрода и возврат демо |
| `specialist` | Журнал и ручное рассмотрение |
| `employee`, `employee2` | Создание и отправка своих заявок |
| `manager` | Согласование заявок других сотрудников |
| `accountant` | Условная выплата и реестр |

Пароль находится в локальном `.env`, значение `DIPLOMA_SEED_PASSWORD`. Откройте файл локально; не отправляйте его содержимое в Git или отчёты. Общий учебный пароль предназначен для локального стенда. Полномочия проверяет сервер.

Для первого прохода создайте заявку сотрудником, отправьте её, согласуйте руководителем и выполните выплату бухгалтером. Начальное правило для выплаты суммы выше 10 000 ₽ требует рассмотрения специалистом. Автор не может согласовать свою заявку; изменение суммы или получателя требует нового согласования. Статус `APPROVED` антифрода и согласование руководителя учитываются отдельно.

### Данные и перезапуск

```powershell
docker compose ps
docker compose restart postgres backend
```

Данные сохраняются в томе `postgres_data`. Для остановки используйте `docker compose stop` (с HTTPS добавьте оба Compose-файла). Не удаляйте том существующего стенда. Возврат демо выполняется явно администратором: прежние заявки сохраняются в архиве, журнал и исполненные операции остаются.

Источник БД по умолчанию ограничен сервером `postgres` и таблицей `demo.requests`. Администратор использует роль `diploma_reader` с локальным `DIPLOMA_READER_PASSWORD`. Ключ `DIPLOMA_SOURCE_ENCRYPTION_KEY` нужно сохранять вместе с существующей конфигурацией источников.

## Проверки и CI

[CI](.github/workflows/ci.yml) запускается при push в `main`, для pull request и вручную. Проверки выполняются в трёх отдельных заданиях:

| Задание | Проверка |
| --- | --- |
| Frontend | `npm ci`, ESLint, TypeScript и production build |
| Backend | Python 3.12.14, зависимости с Linux constraints, `pip check`, строгие pytest-тесты |
| Compose / HTTP | Свежая сборка образа, PostgreSQL, повторный bootstrap, `/health`, восемь HTTP-сценариев с настоящей БД |

HTTP-проверки покрывают роли, оба обязательных этапа, все восемь механизмов и приоритет реакций, настройки и журнал, чтение БД и изменённые значения, сроки и отмену, параллельные вызовы, реестр, архивируемый возврат демо и сохранность после перезапуска. CI генерирует временные секреты, скрывает их в выводе и удаляет только свой временный стенд. Доступ к содержимому репозитория — только для чтения; публикации и деплоя нет. Actions закреплены по SHA, зависимости кэшируются по файлам проекта, задания ограничены по времени.

### Локальные проверки

Создайте новую среду Python 3.12 в корне. Скопированную со старой машины `backend/.venv` не используйте.

```powershell
py -3.12 -m venv .venv
./.venv/Scripts/Activate.ps1
Push-Location backend
python -m pip install -e ".[test]"
python -m pip check
python -m pytest
Pop-Location
npm --prefix frontend run check
docker compose config --quiet
```

Контейнер и Linux CI используют точные runtime-версии из `backend/constraints-linux.txt`. В Windows устанавливаются соответствующие платформе зависимости из `pyproject.toml`.

На отдельном учебном стенде с запущенным backend:

```powershell
Push-Location backend
python tests/http_scenario.py
python tests/http_mechanisms.py
python tests/http_settings.py
python tests/http_source.py
python tests/http_demo_source.py
python tests/http_states.py
python tests/http_restart.py
Pop-Location
```

Эти сценарии создают QA-записи; некоторые временно меняют настройки и перезапускают сервисы. `http_registry_reset.py` отдельно проверяет возврат демо с архивом и заменяет текущие учебные заявки. Его нельзя запускать, если требуется сохранить текущий набор заявок на экране.

Браузерные проверки, нагрузка, TLS и восстановление доставки outbox — отдельные проверки, не входят в обычный CI. Наличие зелёного CI не доказывает достижение целей производительности или совместимость всех браузеров.

## Локальный HTTPS

После production build:

```powershell
docker compose -f docker-compose.yml -f docker-compose.https.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --wait web
./scripts/export-local-ca.ps1
Push-Location backend
python tests/http_tls.py --ca "$env:LOCALAPPDATA/DiplomaValidation/tls/root.crt"
Pop-Location
```

Адрес — https://localhost:8443. Caddy отдаёт production-сборку и API; локальный центр сертификации и его ключи остаются в Docker-томе. Скрипт экспортирует только публичный CA; доверие ОС и браузера автоматически не меняется. Для браузера нужно отдельно доверить этому CA в выбранном профиле. HTTP-тест проверяет сертификат и имя сервера, защищённую cookie, а также отказ неизвестному CA и неверному имени. Отключение проверки сертификата не является проверкой HTTPS.

Порты слушают только `127.0.0.1`, PostgreSQL не опубликован на хосте. Для сетевого стенда нужны отдельная настройка адресов и доверенного сертификата.

## Нагрузка и браузеры

Цели: 10 000 событий, 20 правил, 5 проверок/с в течение 5 минут, ≥95% проверок за 1 с без внешней БД; основные экраны — за 2 с. Чтение внешней БД измеряется отдельно. Результаты относятся к конкретному окружению.

Для воспроизведения нагрузки и подготовки приватного fixture браузерных сценариев:

```powershell
$qaDirectory = Join-Path $env:LOCALAPPDATA 'DiplomaValidation/performance'
New-Item -ItemType Directory -Path $qaDirectory -Force | Out-Null
Push-Location backend
python tests/performance.py --duration 300 --output "$qaDirectory/report.json" --fixture-cache "$qaDirectory/fixture.json"
Pop-Location

./scripts/test-browser-container.ps1 -Browser chromium -Build
./scripts/test-browser-container.ps1 -Browser chromium -Scenario editor
./scripts/test-browser-container.ps1 -Browser firefox
./scripts/test-browser-container.ps1 -Browser firefox -Scenario editor
```

Требуются backend и production-сборка `frontend/dist`. Fixture содержит ключ учебного приложения и остаётся локальным. Браузерный контейнер проверяет настоящие API и данные; сценарий `editor` явно возвращает учебные заявки с архивом. Отчёты и снимки сохраняются в игнорируемой локальной папке. Тесты запускайте последовательно на учебном стенде.

В локальных проверках 05.10.2026: 41 pytest-тест; нагрузка — 1 500 проверок, 0 ошибок, p95 0,0798 с; чтение источника БД — p95 0,2024 с. Chrome и Firefox в Linux прошли основной путь и редакторы правил, основные экраны на истории 10k/20 правил уложились в 2 с. Эти измерения выполнены через локальный HTTP; TLS проверен отдельно. Нативные Chrome/Firefox в Windows пока не проверены из-за ошибки запуска среды.

## Гарантии условного выполнения

Решение связывается с приложением, операцией, действием, инициатором и полным набором проверенных значений, включая источник БД. Финальная транзакция демо блокирует решение и заявку, сверяет значения, срок, полномочия и согласование, затем записывает действие, однократное использование решения и outbox. Потеря доставки факта не позволяет повторить действие.

Отмена использует ту же блокировку: успешная отмена исключает выполнение; после выполнения отмена отклоняется. Срок проверяется в точке допуска перед записью результата; завершение уже допущенной транзакции может произойти позже. Это гарантия условного действия в общей PostgreSQL. Антифрод не получает права записи в подключённую внешнюю БД.

Сроки основаны на времени PostgreSQL. Перед демонстрацией проверьте синхронизацию часов хоста и Docker Desktop. Сетевые гарантии, доверие сертификатам и производительность выбранного целевого стенда требуют проверки именно в этом окружении.
